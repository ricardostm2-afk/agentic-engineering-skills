What can you infer from a 404?

A resource is unavailable. Should the server return 404 or 410? Compare the same situation, changing only what it knows about how long the absence will last.

For readers familiar with GET and response codes. Goal: choose the code from the evidence and limit what the client infers from it. Synthetic cases, analyzed against the standard; no requests were executed.

Compare · Decide · Review a conclusion

The same absence, different knowledge

Worked example: a GET requests a guide with no available representation. In case A, the server does not know how long the absence will last. In B, a recorded policy confirms withdrawal that is likely to be permanent.

What distinguishes the two cases
Case ACase B
404 · Not Found410 · Gone
No information about permanence.Evidence that unavailability is likely to be permanent.
Does not say whether the absence is temporary or permanent.Communicates that access is no longer available and will probably remain so.

Reason for the choice: missing content alone does not decide. In case B, the extra information supports preferring 410. “Likely permanent” does not guarantee it will never change.

Now decide with less help

Another guide has been unavailable for a month. The server keeps no history and has no way to determine whether the condition is permanent. Which code is supported? Explain what information is missing to prefer the other.

A hint, if needed

Does elapsed time replace the information required by the arrow?

Check the decision

404. When permanence is unknown, the standard recommends 404. A month does not provide that certainty. Preferring 410 needs a basis for access having ended and the condition being likely permanent. 404 does not promise a return either.

The resource exists. Does your conclusion change?

An API returns 404 to a visitor without access. The internal catalogue confirms the guide exists; server policy conceals that existence. A colleague proposes the client message: “This guide has been deleted forever.”

Explain whether the 404 contradicts the catalogue, assess the message and propose an alternative supported by the result. The premise changes here: the resource exists and the client does not know the reason for the response.

Compare against the criteria
  1. Existence: 404 is also allowed when the server is unwilling to disclose that a representation exists. It does not necessarily contradict the catalogue.
  2. Duration: 404 does not prove deletion or permanence. The colleague's message goes beyond the evidence.
  3. Client response: for example, “This guide could not be found.” Do not reveal the internal catalogue to the visitor or promise a return.

If you only replaced 404 with 410, reconsider the perspective: you are writing a client message from the observed result, not choosing server policy.
